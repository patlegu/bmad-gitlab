## What holds the score down, and what is done

- **Fixed in the same merge request:** the marker defect (a project name becomes a sprint name that a marker and a list of labels can carry, and the sync says so; two names giving the same sprint are refused; a story key with whitespace is refused), the missing `glab`, the stale "level 2 or 3" docstring.
- **Fixed afterwards, in the order of their weight** (the commit that records this is `fix/client-pages`, version 0.1.3):
  1. The client walks every list through one `_pages` generator with a cap of 1000 pages (`labels`, `issues`, the boards and the lists of a board; the last two were read at page 1 only); `issues()` shrinks to a loop and a `_remote_issue` helper.
  2. Every id read from GitLab (labels, issues, boards, lists) goes through one `_int_field` check, as the writes already did.
  3. `_execute_one`, `_render_action` and `_counts` end in `assert_never`, so a fourth kind of action stops the run instead of being skipped; `apply` sums immutable `Applied` values instead of mutating a string-keyed dict.
  4. `RemoteIssue` lives next to the sprint model, and the client no longer imports the planner.
  5. `auto_apply = "true"` or `gitlab_project = 123` is an error with a message (absent still means false); the test that pinned the silent false was rewritten.
  6. `~~~` blocks are recognised as code, and a block is closed only by its own marker.
  7. The public methods have docstrings.

## What holds

Strict typing, frozen dataclasses, an injected runner with a faithful fake GitLab so that no test reaches the network, an idempotent hash-based marker, `add_labels` and `remove_labels` instead of replacing labels, fail-closed behaviour (no `--apply` with problems, distinct exit codes), a setup that never overwrites a file that is not its own, and a vendoring script with a test that the copy equals the engine.
